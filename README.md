# mini-elf-toolchain

A correctness-focused ELF64 x86-64 toolchain/linker laboratory. The project is intentionally staged so each layer is validated before the next one depends on it.

## Current stage

The repository now has checked ELF64 x86-64 paths for bounded relocatable partial linking (`ET_REL` → `ET_REL`), fixed-address static executables (`ET_REL` → `ET_EXEC`), a bounded static PIE slice (`ET_REL` → `ET_DYN`), and a loader-consumable shared-object producer with bounded runtime relocation, external data/function binding, and loader-driven lazy PLT calls (`ET_REL` → `ET_DYN`). The final-link paths run validated inputs through section extraction, symbol resolution, RELA application, permission-aware layout, mapped `PT_LOAD` / `PT_PHDR` emission, and executable output; both fixed-address static linking and the bounded static PIE path support checked `PT_TLS` emission for the existing local-exec / initial-exec TLS slice. The CLI exposes validation commands, `partial -o <output> <input>...`, and bounded `link -o <output> <input>...` / `link --pie -o <output> <input>...` paths using `_start` as the default entry symbol, with focused GNU binutils differential coverage.

```sh
mini-elf-toolchain partial -o combined.o start.o support.o
mini-elf-toolchain partial -o combined.o start.o libsupport.a
mini-elf-toolchain partial -o combined.o start.o --start-group libfoo.a libbar.a --end-group
mini-elf-toolchain partial -o combined.o start.o --whole-archive libextra.a --no-whole-archive
mini-elf-toolchain partial -o combined.o start.o -L ./lib -lsupport
mini-elf-toolchain partial -o combined.o -u optional_hook start.o -L ./lib -lhooks
mini-elf-toolchain partial -o combined.o start.o -L ./lib -l:custom-support.a
mini-elf-toolchain link -o a.out combined.o
mini-elf-toolchain link -o a.out start.o support.o
mini-elf-toolchain link -o a.out start.o libsupport.a
mini-elf-toolchain link -o a.out start.o -L ./lib -lsupport
mini-elf-toolchain link -o a.out start.o --library-path ./lib --library support
mini-elf-toolchain link -o a.out start.o -L ./lib -l:custom-support.a
mini-elf-toolchain link -o a.out -u optional_hook start.o -L ./lib -lhooks
mini-elf-toolchain link -o a.out start.o --start-group -L ./lib -lfoo -lbar --end-group
mini-elf-toolchain link -o a.out start.o --whole-archive libextra.a --no-whole-archive
mini-elf-toolchain link -o a.out --map a.out.map start.o support.o
mini-elf-toolchain link -o a.out --entry custom_entry start.o support.o
mini-elf-toolchain link -o a.out --image-base 0x800000 start.o support.o
mini-elf-toolchain link --pie -o pie.out start.o support.o
mini-elf-toolchain link --shared -o libanswer.so --soname libanswer.so exports.o
mini-elf-toolchain link --shared -o libconsumer.so --needed libprovider.so consumer.o
mini-elf-toolchain link --shared -o libconsumer.so --needed-from ./lib/libprovider.so consumer.o
mini-elf-toolchain link --shared -o libconsumer.so --needed-from ./deps/libprovider.so --runpath '$ORIGIN/deps' consumer.o
mini-elf-toolchain link --shared -o libconsumer.so -L ./lib -lprovider consumer.o
mini-elf-ar t libsupport.a
mini-elf-ar x libsupport.a support.o
```

The optional deterministic link map records the selected user entry symbol address, allocatable section provenance and addresses, resolved global/weak symbol addresses, and emitted `PT_LOAD` ranges and permissions. `--entry <symbol>` selects a resolved global/weak symbol as the user entry point; `_start` remains the default. `-u <symbol>`, `-u<symbol>`, and `--undefined <symbol>` seed checked unresolved-symbol roots before ordered input processing, allowing otherwise-unreferenced archive members to participate in the existing lazy extraction pipeline. `--image-base <address>` accepts a checked unsigned 64-bit hexadecimal (`0x...`) or decimal base and feeds it through the fixed-address `ET_EXEC` layout/emission pipeline; the default remains `0x400000`. `--pie` instead lays the bounded image out from virtual address zero and emits an `ET_DYN` main executable with mapped `PT_LOAD` / `PT_PHDR` metadata and no `PT_INTERP`; `--pie` and `--image-base` are mutually exclusive before input I/O. Load-bias-invariant PC-relative forms (`PC8`/`PC16`/`PC32`/`PC64`/`PLT32`) plus `SIZE32`/`SIZE64` remain direct link-time relocations. The PIE path now accepts two bounded runtime-relocation surfaces. Writable-target `R_X86_64_64` references to image-backed definitions become symbol-free `R_X86_64_RELATIVE` entries, and PC-relative ordinary GOT references (`GOTPCREL` / `GOTPCREL64` / `GOTPCRELX` / `REX_GOTPCRELX`) reuse the deterministic synthetic GOT while adding one `R_X86_64_RELATIVE` per image-backed GOT slot. Multiple references to the same symbol still share one slot and therefore one runtime relocation. `SHN_ABS` GOT targets keep their fixed slot value and do not create a dynamic plane. When any runtime relocation is required, the image gains a real `PT_DYNAMIC` table with `DT_RELA` / `DT_RELASZ` / `DT_RELAENT` / `DT_RELACOUNT`, and a synthetic x86-64 entry trampoline derives the kernel load bias, applies every relative relocation, then transfers control to the selected user entry. PIEs without eligible runtime relocations keep the no-`PT_DYNAMIC` path. Runtime-relative conversion remains restricted to file-backed writable targets and image-backed normal definitions; unresolved weak zero semantics, text relocations, 32-bit absolute forms, GOT32/GOT64/GOT-base/GOTOFF PIE semantics, dynamic TLS relocation, PLT construction, and external dynamic symbol binding remain fail-closed or out of scope. The PIE path now also composes with the existing static TLS model: `R_X86_64_TPOFF32` and `R_X86_64_GOTTPOFF` stay load-bias invariant, TLS-specific GOT slots retain signed thread-pointer offsets rather than becoming runtime-relative GOT entries, and the ET_DYN image carries checked `PT_TLS` metadata. The linker still does not allocate per-thread TLS storage or install a thread pointer; executable fixtures perform explicit single-thread FS-base setup before exercising local-/initial-exec TLS. GNU `readelf` dynamic-relocation differentials verify the emitted metadata, GNU `ld -pie --no-dynamic-linker` supplies the relocation-family reference, and Linux execution dereferences a relocated absolute pointer to prove the self-relocator actually runs. Page alignment remains fixed at `0x1000`. A separate bounded `--shared` producer now emits loader-consumable `ET_DYN` DSOs with a mapped `PT_DYNAMIC`, SysV `DT_HASH`, `DT_STRTAB`, `DT_SYMTAB`, `DT_STRSZ`, and `DT_SYMENT`; exported default-visible global/weak function and data symbols are verified through GNU dynamic inspection plus a real glibc `dlopen`/`dlsym` consumer. The shared-object path accepts three loader-applied relocation slices. Writable-target `R_X86_64_64` references to local/non-preemptible definitions become symbol-free `R_X86_64_RELATIVE` entries. Undefined default-visible global/weak `STT_OBJECT` references through writable-target `R_X86_64_64` remain symbol-based dynamic relocations backed by matching undefined `.dynsym` entries. Weak data imports preserve ELF zero-or-bind semantics: absent definitions resolve to zero, while visible host/provider definitions bind normally. Canonical external-data `GOTPCREL` references reuse the deterministic synthetic GOT: the instruction is resolved at link time to a zero-initialized writable GOT slot, while the loader fills that slot through `R_X86_64_GLOB_DAT`; weak `STT_OBJECT` GOT imports follow the same zero-or-bind rule. GNU's synthetic undefined `_GLOBAL_OFFSET_TABLE_` input symbol is recognized as linker-owned only when such a GOT is actually present and is never emitted as a loader import. glibc `dlopen(RTLD_NOW)` fixtures bind both direct and GOT-based imports to data exported by a `-rdynamic` main executable, and the GOT fixture proves an exported DSO function observes subsequent host-side value changes through the patched slot. Internal RELATIVE entries remain first in the combined RELA table so `DT_RELACOUNT` continues to describe exactly the relative prefix. Shared-object alloc layout reserves a nonzero first page so loader-visible defined symbols do not accidentally use `st_value == 0`. Defined shared TLS exports are supported as a bounded loader-allocation slice: checked .tdata/.tbss layout is published through PT_TLS, exported STT_TLS dynamic symbols use module-relative TLS-block offsets, and glibc dlopen/dlsym plus pthread execution proves initialized and zero-fill TLS instances are independently allocated per thread. The shared path now also supports a first executable general-dynamic TLS access slice for defined STT_TLS symbols: real R_X86_64_TLSGD instruction relocations target deterministic 16-byte descriptors in the writable synthetic GOT region, those descriptors receive loader-applied R_X86_64_DTPMOD64 and R_X86_64_DTPOFF64 relocations against the defined TLS dynsym entry, and __tls_get_addr uses the existing lazy PLT/JUMP_SLOT machinery. A dlopen fixture proves main-thread mutation plus independent pthread TLS instances through exported read/write functions. Strong undefined STT_TLS symbols are now supported on the same TLSGD path across a DSO boundary: the consumer emits an undefined TLS dynsym entry plus DTPMOD64/DTPOFF64 descriptor relocations, checked provider matching requires a same-name STT_TLS export, and DT_NEEDED/RUNPATH lets glibc bind the descriptor to the provider's PT_TLS allocation. A provider/consumer pthread fixture proves independent per-thread instances survive that cross-DSO binding. Same-DSO local-dynamic TLS is also supported for defined local STT_TLS symbols: real R_X86_64_TLSLD references share one deterministic 16-byte module descriptor per DSO, that descriptor receives one symbol-index-zero R_X86_64_DTPMOD64 relocation, and R_X86_64_DTPOFF32 sites are patched after final PT_TLS layout with checked module-relative offsets. The existing __tls_get_addr lazy PLT/JUMP_SLOT path resolves the module base, while GNU readelf plus dlopen/pthread fixtures prove initialized .tdata and zero-fill .tbss values remain thread-local. Shared-object initial-exec TLS is supported for defined default-visible strong STT_TLS symbols and strong undefined default-visible STT_TLS imports. R_X86_64_GOTTPOFF resolves at link time to the existing deterministic 8-byte TLS GOT slot, the loader fills that slot through R_X86_64_TPOFF64 against either the defined TLS dynsym entry or the imported undefined TLS dynsym entry, and the dynamic table publishes DT_FLAGS=DF_STATIC_TLS. Cross-DSO imports reuse exact STT_TLS provider matching plus DT_NEEDED/RUNPATH, and GNU readelf plus dlopen/pthread execution prove provider-backed initialized TLS retains independent per-thread instances across the DSO boundary. Shared local-exec R_X86_64_TPOFF32 remains fail-closed. The shared producer now owns bounded same-DSO and strong cross-DSO TLSDESC slices: GNU-style R_X86_64_GOTPC32_TLSDESC address relocations target deterministic writable 16-byte descriptors, R_X86_64_TLSDESC_CALL markers are preserved as instruction-sequence markers rather than ordinary numeric relocations, and the loader fills each descriptor through R_X86_64_TLSDESC against the defined STT_TLS dynsym entry. GNU dynamic inspection plus glibc dlopen/pthread execution prove the descriptor model preserves independent per-thread values without relaxing to TLSGD, initial-exec, or local-exec. Weak/nonlocal TLSLD, cross-DSO TLSLD, weak initial-exec TLS, and weak TLSDESC imports remain fail-closed. Weak PLT call semantics, legacy producer-side RPATH, system/default loader-path emulation at link time, general interposition, general linker scripts, arbitrary section placement, weak TLS imports, cross-DSO/nonlocal TLSLD, weak initial-exec TLS, weak TLSDESC imports, shared-object local-exec TLS generation, TLS-model relaxation, CET/IBT PLT variants, and alternate architectures remain outside the current scope. Producer-side RUNPATH is supported through checked `--runpath <path>` / `--runpath=<path>` in shared mode; the exact string is stored in the existing loader-visible dynamic string table and published as `DT_RUNPATH`. A glibc fixture loads a `DT_NEEDED` provider from `$ORIGIN/deps` with no `LD_LIBRARY_PATH`, then exercises both the provider PLT/JUMP_SLOT function binding and GOT/GLOB_DAT data binding. RUNPATH is also consumed by bounded build-time provider-closure inspection for transitive `DT_NEEDED` edges. Each inspected provider's direct dependency search uses the provider directory first, then checked `DT_RUNPATH` entries, then explicit shared `-L` paths. Closure expansion supports absolute entries plus `$ORIGIN` / `${ORIGIN}` forms relative to that provider's directory; empty entries, ordinary relative entries, and unsupported loader tokens fail closed. Runtime loading remains delegated to glibc, and a no-`LD_LIBRARY_PATH` fixture proves consumer `$ORIGIN` plus provider `$ORIGIN/deps` resolve a root→deep dependency chain. Producer-side SONAME is supported through checked `--soname <name>` / `--soname=<name>`; the emitted `DT_SONAME` shares the loader-visible dynamic string table and is validated by GNU `readelf`. A self-hosting fixture feeds a mini-produced SONAME provider back through the checked `--needed-from` inspector, proves the consumer records that SONAME as `DT_NEEDED`, and then uses glibc `dlopen` with `LD_LIBRARY_PATH` to execute the provider's function/data bindings. The shared CLI can record ordered, deduplicated `DT_NEEDED` dependencies either explicitly with `--needed`, from a checked provider path with `--needed-from`, or through bounded shared-mode `-L/-l` search. Provider-backed dependency paths reuse one checked ELF64 `ET_DYN` inspector: it requires loader-facing `PT_DYNAMIC`, checked SysV `DT_HASH`, GNU `DT_GNU_HASH`, or both, dynsym/strtab metadata, and a non-empty `DT_SONAME`. A root provider that directly matches at least one canonical bounded consumer import preserves the existing direct-provider path. When the root itself matches none, bounded build-time closure inspection follows its checked `DT_NEEDED` graph breadth-first, resolving each dependency only from the current provider directory plus the original shared `-L` search scope, validating every traversed DSO with the same inspector, and deduplicating canonical paths so cycles terminate. A transitive match validates the provider choice without flattening dependency metadata: the consumer still records only the selected root provider SONAME as `DT_NEEDED`, leaving the loader to follow that provider's own dependencies. Named-version strong `STT_OBJECT`, `STT_FUNC`, and `STT_TLS` imports are supported through both direct checked providers and the bounded checked transitive provider closure: GNU `.symver` undefined names such as `provider_value@VERS_1`, `provider_function@VERS_1`, or `provider_tls@VERS_1` keep their raw linker identity for relocation/TLS bookkeeping, emit the canonical base name in `.dynsym`, and receive a checked external `DT_VERSYM` index backed by `DT_VERNEED` / `DT_VERNEEDNUM` for the DSO that actually exports the requested version. A transitive version match preserves root-only `DT_NEEDED` metadata while allowing `DT_VERNEED` to name the checked reachable leaf provider; the standalone version inspector validates such non-direct requirements through the same provider-directory / RUNPATH closure resolver rather than accepting arbitrary VERNEED filenames. Versioned functions compose with all three bounded function binding planes—PLT32/JUMP_SLOT, GOTPCREL/GLOB_DAT, and writable `R_X86_64_64` function pointers. Versioned TLS composes one requested TLS symbol across general-dynamic TLSGD/DTPMOD64/DTPOFF64, initial-exec GOTTPOFF/TPOFF64, and TLSDESC, with the shared relocation evaluator allowing those synthetic TLS models to coexist for one unresolved symbol while preserving fail-closed behavior for ordinary unresolved relocations. Provider matching uses the provider's checked `DT_VERDEF` namespace plus symbol type, mismatched versions fail before output, and GNU dynamic-symbol inspection plus the project's version-namespace checker and glibc `dlopen`/pthread fixtures prove loader binding to the requested version and per-thread TLS identity. Producer-side GNU `.symver` definitions now support both default `name@@VERSION` and non-default `name@VERSION` aliases. Raw linker identities stay available for relocation/TLS bookkeeping while multiple versioned dynsym entries may share one canonical loader-facing base name; at most one default/unversioned export is allowed per canonical name. Non-default aliases carry the GNU `VERSYM_HIDDEN` bit, while deterministic `DT_VERDEF` indices remain shared by version name and continue to coexist with external `DT_VERNEED` requirements in one non-colliding namespace. GNU dynamic inspection plus glibc `dlsym`/`dlvsym` fixtures prove default lookup selects the `@@` alias, explicit version lookup selects the hidden `@` alias, and one mini-produced consumer can bind two versions of the same provider symbol simultaneously. A bounded producer `--version-script` subset now assigns ordinary unversioned definitions to default named versions using multiple independent blocks with exact `global:` symbol names; `local: *;` removes unlisted definitions from the loader-facing export surface without changing internal symbol resolution or relocation identity. Script-selected exports reuse the same `DT_VERSYM` / `DT_VERDEF` namespace as producer `.symver` definitions, while unmatched script symbols, inheritance, global wildcard matching, named local patterns, and mixing scripts with explicit producer `.symver` aliases fail closed. GNU dynamic inspection, the project version checker, and glibc `dlsym`/`dlvsym` execution verify the generated default-version exports and localized private symbols. Version-script inheritance/pattern language, weak versioned TLS and broader weak-versioned import semantics beyond function-address binding, versioned TLSLD, and general interposition/version-script semantics remain outside this bounded slice. Shared-mode search prefers `lib<name>.so` over `lib<name>.a` within each search directory; absent `.so` candidates preserve the existing static-archive fallback, while selected DSOs stay out of the ET_REL/archive input stream. A two-provider fixture also proves first-declared `DT_NEEDED` order controls the consumer dependency symbol scope. Strong external `STT_FUNC` symbols are supported through direct writable `R_X86_64_64` function pointers, GOTPCREL/GLOB_DAT slots, and direct `R_X86_64_PLT32` calls. The PLT32 path now emits a conventional bounded x86-64 lazy PLT/GOTPLT layout: a 16-byte PLT0 resolver entry, three reserved GOTPLT runtime slots, and one deterministic 16-byte symbol stub per import. Each symbol slot initially points to that stub's push path, the stub pushes its deterministic `DT_JMPREL` relocation index and jumps back to PLT0, and `DT_PLTGOT` is published alongside `DT_JMPREL` / `DT_PLTRELSZ` / `DT_PLTREL` without `DT_BIND_NOW`. A glibc `dlopen(RTLD_LAZY)` fixture reads the live GOTPLT slot through `dlinfo(RTLD_DI_LINKMAP)`, proves it is unresolved before the first call, observes the loader rewrite it to the host function, and verifies the second call reuses the unchanged resolved slot.

Archive support includes a checked System V/GNU/BSD `ar` parser, validated `/` and `/SYM64/` symbol-index parsing, unresolved-symbol-driven lazy member extraction, ordered orchestration for regular `ET_REL` objects plus archives, bounded GNU-style `--start-group ... --end-group` rescanning for circular dependencies across archives, stateful `--whole-archive` / `--no-whole-archive` force inclusion, bounded static `-L` / `-l` library search, GNU-style exact-name `-l:filename` lookup, and GNU-style forced undefined roots. BSD `#1/<len>` extended names are decoded from the inline filename prefix while preserving the raw member header offset and exposing only the remaining bytes as the object payload; malformed lengths and filename ranges are checked before slicing. `-L <dir>`, `-L<dir>`, `--library-path <dir>`, and `--library-path=<dir>` add checked search directories in order; `-l <name>`, `-l<name>`, `--library <name>`, and `--library=<name>` resolve deterministically to the first existing `lib<name>.a` in those directories, while exact-name `:filename` works with the short and long library forms without adding a `lib` prefix or `.a` suffix. The resulting archive remains at the original command-line position. Empty or missing split/equals values are rejected before link input I/O, and a missing exact library reports the requested filename and searched directories. Static/fixed/PIE and partial-link modes keep this bounded archive-only resolver. Shared mode layers checked provider lookup onto the same ordered search directories: each directory prefers `.so` before `.a`, exact `-l:*.so*` names are treated as provider DSOs, and selected providers are validated through the same SONAME/export contract as `--needed-from`. The public `link` CLI preserves left-to-right input order, performs ordinary archive extraction only when an archive is encountered, does not implicitly rescan earlier archives outside an explicit group, and feeds selected archive members through the same validated `LinkerInputObject` and static-link pipeline as regular objects. Forced undefined roots are deduplicated through the resolver's ordered symbol state and are satisfied by earlier regular definitions or by subsequent archive extraction. Whole-archive mode validates and includes every ordinary member in archive order and intentionally does not require a System V/GNU symbol index; special archive members such as `/`, `/SYM64/`, and `//` are not treated as linkable objects. Within a group, the first pass preserves all input order and subsequent passes rescan only ordinary lazy archives; whole-archive inputs are force-included once and are not duplicated by group rescans. The number of lazy group passes is bounded by the checked total number of ordinary members in lazy archives, which is sufficient because every productive rescan must extract at least one previously unselected member. Nested groups are intentionally rejected in this bounded first slice. Extraction validates each selected member as ELF64 x86-64 `ET_REL`, propagates strong undefined references introduced by extracted members, does not let weak undefined references pull additional members, and leaves unreferenced members unparsed outside whole-archive mode. Member headers, sizes, payload bounds, padding, GNU short/long names, BSD extended names, symbol counts, big-endian member offsets, symbol strings, and index-to-member references are validated with checked arithmetic and GNU/LLVM differential coverage. BSD ranlib symbol-table parsing and thin archives remain intentionally unsupported. The companion `mini-elf-ar` CLI provides checked ordinary-member listing (`t`), bounded safe extraction (`x`) with exact-name member selection, and deterministic creation-only indexed archives through `rcs` / `crs`. Creation validates every ELF64 x86-64 `ET_REL` member before filesystem mutation, emits a checked SysV32 symbol index plus GNU long-name table when needed, and refuses to overwrite an existing archive. Extraction validates the complete archive and output plan before creating files, rejects path-traversal-style or duplicate output names, and uses no-clobber creation so existing files and symlinks are never overwritten. Replacement/deletion/reordering, metadata restoration, thin archives, BSD ranlib emission, overwrite mode, and directory-preserving extraction remain outside this bounded slice.

Bounded partial linking emits conventional `ET_REL` output with deterministic `.symtab`, `.strtab`, and `.shstrtab` tables, remapped symbol section indices, and retargeted RELA symbol/target references. Compatible canonical `.text`, `.rodata`, `.data`, and `.bss` contributions are coalesced in input order: each contribution keeps its required alignment, defined symbol `st_value` fields are rebased by the contribution offset, RELA `r_offset` fields are rebased to the merged output section, same-name RELA tables targeting the same canonical output section are combined, and merged `.bss` remains `SHT_NOBITS`. Other allocatable section names remain independent so semantic sections such as `.eh_frame`, TLS sections, and custom alloc sections are not merged accidentally. Cross-object global/weak symbols are canonicalized by name so all original relocation symbol indices retarget one output symbol; undefined references resolve to available definitions, strong definitions supersede weak definitions, multiple real strong definitions fail before output, and `SHN_COMMON` candidates merge by maximum size/alignment while remaining common in the emitted ET_REL. The partial CLI also accepts ordinary indexed archives in the same left-to-right input stream: strong unresolved symbols drive the existing checked lazy-extraction pipeline to a fixed point within each archive, selected members feed the same ET_REL canonicalizer, unreferenced members remain excluded, and later unresolved symbols do not retroactively rescan an earlier archive. Explicit `--start-group ... --end-group` regions reuse the bounded final-link group engine: the first pass preserves input order and later passes rescan only lazy archives, with the number of passes bounded by the checked total ordinary-member count. This resolves circular archive dependencies without changing ordinary non-group ordering. `--whole-archive` / `--no-whole-archive` state is also shared with final linking: every ordinary member is validated and included in archive order, no symbol index is required, and special archive members remain non-linkable metadata. The partial CLI shares the final linker's bounded static-library resolver and forced-undefined argument parser: `-L` / `--library-path`, `-l` / `--library`, exact-name `-l:filename`, and `-u` / `--undefined` roots compose with the same ordered archive pipeline. Forced roots can select otherwise-unreferenced archive members and their transitive dependencies; unmatched roots remain global undefined symbols in the emitted ET_REL, while an existing same-name real global/weak symbol keeps its binding/metadata. Nested partial groups remain fail-closed even though the reusable library resolver can canonicalize balanced nested markers for the final-link CLI. Serializer failures for selected members retain archive/member provenance. GNU `ld -r` differential coverage checks canonical alloc-section counts, contribution alignment, merged relocation offsets/tables, canonical symbol/common records, forced-root behavior, duplicate-definition behavior, transitive archive extraction, and archive ordering; the emitted object is then consumed by both this project's final static linker and GNU `ld -static`, with both executables run on Linux. Identical input order produces byte-identical output, and malformed later inputs fail before the output file is written. Bounded COMDAT handling accepts validated `SHT_GROUP` / `GRP_COMDAT` groups containing preserved allocatable members and their grouped `SHT_RELA` metadata, and now performs deterministic duplicate-signature selection. Grouped alloc sections remain independent from canonical section coalescing; grouped RELA sections keep their flags/alignment/entry-size metadata, are retargeted to the rebuilt static symbol table and remapped group member target, and are emitted before the group so the final `SHT_GROUP` member list can reference their new output section indices. For duplicate `GRP_COMDAT` signatures, the first group in input order wins, matching GNU `ld -r`; loser alloc/RELA members and unreferenced loser globals are discarded before ET_REL emission, while a loser global/weak definition still referenced by surviving relocation metadata is retained as undefined so the relocation remains representable and can resolve against a selected same-name definition. Discarded local definitions remain unmapped so illegal surviving local references fail closed. GNU `readelf --section-groups`, GNU `ld -r`, the project validator, reverse-order selection fixtures, and both mini/GNU final-link execution verify the resulting ET_REL behavior. Grouped RELA must use the group's static symbol table and target another member of the same group; any non-alloc section that retains `SHF_GROUP` without actual membership in a supported `SHT_GROUP` fails closed rather than producing orphan group metadata. The bounded slice also remains fail-closed on `SHN_XINDEX` symbols and non-default nonlocal `st_other` visibility. Dynamic symbol tables, visibility/interposition semantics, unrelated non-allocatable semantic sections, push/pop state in the partial command, non-COMDAT/associative group semantics, broader GNU section-merging rules, shared-library lookup, and general GNU `ld -r` semantics remain outside this phase.

The bounded relocation set includes absolute and PC-relative 8/16/32/64-bit forms already exercised by the static linker, `R_X86_64_SIZE32` / `R_X86_64_SIZE64`, a real static-GOT slice for `R_X86_64_GOT32`, `R_X86_64_GOT64`, `R_X86_64_GOTPCREL`, `R_X86_64_GOTPCRELX`, and `R_X86_64_REX_GOTPCRELX`, plus bounded static TLS support for local-exec `R_X86_64_TPOFF32` and initial-exec `R_X86_64_GOTTPOFF`. SIZE relocations use the resolved definition's ELF `st_size` (`Z`) and apply the ABI `Z + A` formula with checked unsigned-width conversion, so cross-object references do not incorrectly rely on the undefined reference-side symbol metadata. Ordinary GOT-family references collect unique global/weak symbols deterministically, allocate 8-byte entries in a synthetic writable `SHT_PROGBITS` region, and initialize those entries with final resolved symbol addresses. `R_X86_64_GOT32` and `R_X86_64_GOT64` write checked unsigned `G + A` values at 32-bit and 64-bit widths respectively, where `G` is the selected entry's offset from the synthetic GOT base; GOTPCREL-family relocations apply the signed `GOT-entry + A - P` displacement. Initial-exec TLS uses a separate deterministic namespace of GOT slots in that same synthetic region: `GOTTPOFF` relocations address the TLS-specific slot, while the slot itself is materialized after final TLS layout with the signed thread-pointer offset `S - TLS_base - TLS_block_size`. This separation lets ordinary address GOT entries and TLS-offset GOT entries coexist without conflating their value semantics. Static TLS layout emits a checked `PT_TLS` program header spanning initialized `.tdata` and memory-only `.tbss` for both fixed ET_EXEC and bounded ET_DYN PIE output. GNU differential fixtures exercise local-exec and initial-exec behavior; the PIE fixture additionally composes TLS with the self-relocation trampoline and an ordinary runtime-relocated GOT slot, while explicit single-thread FS-base setup keeps process-level TLS allocation outside the linker. The relaxable GOTPCRELX relocation kinds remain accepted as non-relaxed GOT references. The shared-object producer deliberately keeps a narrow runtime-relocation surface: writable-target `R_X86_64_64` references to local/non-preemptible definitions become symbol-free `R_X86_64_RELATIVE`; undefined default-visible global/weak `STT_OBJECT` references through writable-target `R_X86_64_64` remain symbol-based for loader resolution, with unresolved weak data symbols resolving to zero; and canonical external-data `GOTPCREL` references allocate a synthetic writable GOT slot that is resolved by the loader through `R_X86_64_GLOB_DAT`, including the same weak-data zero-or-bind semantics. Unresolved GOT handling is explicitly scoped to the shared path so ordinary static linking remains fail-closed. Defined default-visible global/weak relocation targets still fail closed because general interposition is not implemented. Undefined weak `STT_OBJECT` data imports and weak `STT_FUNC` address imports are supported on the direct `R_X86_64_64` and GOT/GLOB_DAT paths with loader zero-or-bind semantics; weak PLT/JUMP_SLOT calls remain fail-closed. Defined shared TLS exports are permitted without TLS relocations: the producer emits a checked PT_TLS image and module-relative STT_TLS dynamic-symbol values for loader allocation. Defined strong same-DSO initial-exec references now reuse the TLS GOT and publish loader-applied R_X86_64_TPOFF64 plus DF_STATIC_TLS; shared local-exec R_X86_64_TPOFF32 remains rejected. Instruction rewriting/relaxation beyond the bounded lazy PLT stub family, CET/IBT PLT variants, producer-side legacy RPATH, system/default loader-path resolution, weak TLS imports, weak/nonlocal or cross-DSO TLSLD, weak initial-exec TLS, weak TLSDESC imports, shared-object local-exec TLS code generation, TLS-model relaxation, and general symbol interposition remain outside the current bounded linker scope. Same-DSO defined strong TLSDESC access is supported as a distinct descriptor model and is not relaxed to TLSGD, initial-exec, or local-exec. Strong cross-DSO STT_TLS imports are supported only through the bounded TLSGD descriptor path. The bounded TLSGD slice, for both defined and strong imported STT_TLS symbols, owns only the DTPMOD64/DTPOFF64 descriptor pair needed by __tls_get_addr. Producer-side `DT_SONAME` emission is now part of the bounded shared path and composes with checked provider inspection / `DT_NEEDED` inference. Ordered `DT_NEEDED` recording supports explicit names, checked `--needed-from` providers, and one-level shared-mode `-L/-l` provider search; provider-backed paths accept checked SysV `DT_HASH`, GNU `DT_GNU_HASH`, or both, require a non-empty SONAME, and require at least one symbol-type-compatible consumer import. GNU-hash-only providers are validated with checked header/bloom/bucket/chain bounds and derive a bounded dynamic-symbol count from the hash topology when no SysV `nchain` is available. Strong external function symbols can bind through direct writable `R_X86_64_64` slots, GOTPCREL/GLOB_DAT, or eager PLT32 → synthetic PLT → JUMP_SLOT.

Global `SHN_COMMON` tentative symbols are merged by maximum size and alignment, with a real strong definition taking precedence. Surviving commons are placed deterministically by symbol name into one synthetic writable `SHT_NOBITS` region, so existing relocation, symbol-address, load-segment, and link-map paths all observe the same final allocation. Common alignment must be a non-zero power of two, and alignment/size arithmetic is checked for overflow.

The current checkpoint is deliberately a bounded ELF toolchain core, not a partial promise of a full system linker. A conventional first-slice `ET_REL` partial-link emitter, a small validated linker-script subset, bounded static TLS local-/initial-exec models, and a self-relocating static `ET_DYN` PIE slice are explicit milestones already in scope. The PIE path now owns a minimal runtime relocation plane for symbol-free `R_X86_64_RELATIVE`, including bounded image-backed ordinary GOT slots reached through PC-relative GOT references, and it can reuse the static TLS local-/initial-exec layout without making TLS GOT slots load-bias relocations. It deliberately stops before a general dynamic linker or TLS runtime. A bounded shared-object producer now owns loader-facing SysV dynamic symbol/hash metadata, an internal symbol-free `R_X86_64_RELATIVE` plane, a direct symbol-based external data-import plane through `R_X86_64_64`, and a PIC external-data plane that resolves `GOTPCREL` instructions to synthetic GOT slots patched by loader-applied `R_X86_64_GLOB_DAT`. Both data planes support undefined weak `STT_OBJECT` zero-or-bind semantics; same-name strong references canonicalize the emitted import back to `GLOBAL`, while conflicting import symbol types fail closed. glibc `dlopen` fixtures prove same-image relocation, direct main-executable symbol binding, mixed RELATIVE/import ordering, and live GOT-based reads of host-exported data. Explicit ordered `DT_NEEDED` dependency recording is now present and glibc fixtures prove DSO-to-DSO provider loading plus first-needed symbol-scope precedence. Provider inference can also validate a root provider through a bounded checked transitive `DT_NEEDED` closure when the root itself exports none of the consumer imports; GNU fixtures prove function/data binding through a middle→deep dependency, checked parent-provider `DT_RUNPATH` lookup with bounded `$ORIGIN` expansion, shared `-L` fallback, missing-dependency fail-closed behavior, and canonical-path cycle termination while the consumer retains only the direct root `DT_NEEDED`. Provider inspection now also validates GNU `DT_VERSYM` / `DT_VERDEF`: ordinary unversioned consumer imports may match unversioned/global exports or non-hidden default-version exports, while hidden non-default-only exports and orphan defined version indices fail closed; GNU `ld -z defs` and glibc runtime fixtures verify the same boundary. Named-version strong `STT_OBJECT`, `STT_FUNC`, and `STT_TLS` consumer imports now carry loader-visible GNU version requirements through either a direct checked provider or a checked transitive provider closure. The producer canonicalizes the dynamic symbol name, emits external `DT_VERSYM` plus `DT_VERNEED` / `DT_VERNEEDNUM` tied to the actual version-exporting provider SONAME, keeps only the selected root provider in `DT_NEEDED`, rejects mismatched requested versions before output, and is verified by the project's closure-aware checked version inspector plus glibc runtime binding. Versioned function imports are exercised across PLT/JUMP_SLOT, GOT/GLOB_DAT, and relocated function-pointer paths against a mini-produced `@@VERSION` provider; versioned TLS is exercised across TLSGD, initial-exec, and TLSDESC in one consumer, with cross-model reads/writes proving the same provider TLS instance within a thread and independent initialization across pthreads. Multiple parents per version definition, broader wildcard/pattern matching beyond the bounded non-empty literal-prefix trailing-`*` form (including leading/infix `*`, `?`, and character classes), named local patterns and other general script-language semantics, weak versioned TLS/import semantics, versioned TLSLD, legacy producer-side RPATH, system/default loader-path resolution, `$LIB` / `$PLATFORM` expansion and ordinary relative RUNPATH entries, weak PLT-call semantics, CET/IBT PLT variants, general interposition/versioning, broader GOT32/GOT64/GOT-base/GOTOFF runtime semantics, weak TLS imports, weak/nonlocal or cross-DSO TLSLD, weak initial-exec TLS, weak TLSDESC imports, shared-object local-exec TLS generation, and TLS-model relaxation remain future architectural phases. Defined same-DSO and strong cross-DSO TLSDESC generation are now closed as bounded loader-executed milestones: GNU-assembled address/call relocations resolve through deterministic descriptors, one loader `R_X86_64_TLSDESC` relocation initializes each descriptor, imported descriptors bind through checked `STT_TLS` providers and `DT_NEEDED`/RUNPATH, and dlopen/pthread execution proves independent per-thread read/write behavior. Defined-symbol and strong cross-DSO imported TLSGD plus DTPMOD64/DTPOFF64, same-DSO local-dynamic TLSLD/DTPOFF32 plus one DTPMOD64 module descriptor, and defined plus strong cross-DSO imported initial-exec GOTTPOFF/TPOFF64 plus DF_STATIC_TLS are now closed as bounded loader-executed milestones. Defined shared TLS export/allocation is now closed as a bounded milestone: glibc allocates independent per-thread .tdata/.tbss instances for mini-produced PT_TLS images, verified through dlsym and pthread execution. Producer-side `DT_RUNPATH` is now closed as a bounded runtime-loader milestone: exact strings including `$ORIGIN` and colon-separated entries are emitted, and glibc execution proves a mini-produced consumer can locate a direct `DT_NEEDED` provider without `LD_LIBRARY_PATH`. Producer-side SONAME is now closed as a milestone: mini-produced providers can carry a checked `DT_SONAME` and round-trip through the project's own provider inspector / dependency inference path before glibc loads the resulting consumer/provider pair. Strong external functions are now callable through loader-patched ordinary GOT slots, direct writable function-pointer relocations, and loader-driven lazy PLT/JUMP_SLOT stubs whose GOTPLT slot transition is verified across first and second calls. Broader dynamic linking, the general GNU linker-script language, dynamic TLS models, LTO, and alternate architectures should only enter through explicit future milestones rather than incidental feature growth.

Each new capability should include focused malformed-input tests. Offsets, sizes, addresses, alignment, and relocation arithmetic must use checked operations where overflow can make an input invalid.
