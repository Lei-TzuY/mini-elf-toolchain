# mini-elf-toolchain

A correctness-focused ELF64 x86-64 toolchain/linker laboratory. The project is intentionally staged so each layer is validated before the next one depends on it.

## Current stage

The repository now has checked ELF64 x86-64 paths for bounded relocatable partial linking (`ET_REL` → `ET_REL`), fixed-address static executables (`ET_REL` → `ET_EXEC`), a bounded static PIE slice (`ET_REL` → `ET_DYN`), and a loader-consumable shared-object producer with bounded runtime relocation, external data/function binding, and eager PLT calls (`ET_REL` → `ET_DYN`). The final-link paths run validated inputs through section extraction, symbol resolution, RELA application, permission-aware layout, mapped `PT_LOAD` / `PT_PHDR` emission, and executable output; both fixed-address static linking and the bounded static PIE path support checked `PT_TLS` emission for the existing local-exec / initial-exec TLS slice. The CLI exposes validation commands, `partial -o <output> <input>...`, and bounded `link -o <output> <input>...` / `link --pie -o <output> <input>...` paths using `_start` as the default entry symbol, with focused GNU binutils differential coverage.

```sh
mini-elf-toolchain partial -o combined.o start.o support.o
mini-elf-toolchain partial -o combined.o start.o libsupport.a
mini-elf-toolchain partial -o combined.o start.o --start-group libfoo.a libbar.a --end-group
mini-elf-toolchain partial -o combined.o start.o --whole-archive libextra.a --no-whole-archive
mini-elf-toolchain partial -o combined.o start.o -L ./lib -lsupport
mini-elf-toolchain partial -o combined.o -u optional_hook start.o -L ./lib -lhooks
mini-elf-toolchain partial -o combined.o start.o -L ./lib -l:custom-support.a
mini-elf-toolchain link -o a.out combined.o
mini-elf-toolchain link -o a.out start.o support.o
mini-elf-toolchain link -o a.out start.o libsupport.a
mini-elf-toolchain link -o a.out start.o -L ./lib -lsupport
mini-elf-toolchain link -o a.out start.o --library-path ./lib --library support
mini-elf-toolchain link -o a.out start.o -L ./lib -l:custom-support.a
mini-elf-toolchain link -o a.out -u optional_hook start.o -L ./lib -lhooks
mini-elf-toolchain link -o a.out start.o --start-group -L ./lib -lfoo -lbar --end-group
mini-elf-toolchain link -o a.out start.o --whole-archive libextra.a --no-whole-archive
mini-elf-toolchain link -o a.out --map a.out.map start.o support.o
mini-elf-toolchain link -o a.out --entry custom_entry start.o support.o
mini-elf-toolchain link -o a.out --image-base 0x800000 start.o support.o
mini-elf-toolchain link --pie -o pie.out start.o support.o
mini-elf-toolchain link --shared -o libanswer.so --soname libanswer.so exports.o
mini-elf-toolchain link --shared -o libconsumer.so --needed libprovider.so consumer.o
mini-elf-toolchain link --shared -o libconsumer.so --needed-from ./lib/libprovider.so consumer.o
mini-elf-toolchain link --shared -o libconsumer.so -L ./lib -lprovider consumer.o
mini-elf-ar t libsupport.a
mini-elf-ar x libsupport.a support.o
```

The optional deterministic link map records the selected user entry symbol address, allocatable section provenance and addresses, resolved global/weak symbol addresses, and emitted `PT_LOAD` ranges and permissions. `--entry <symbol>` selects a resolved global/weak symbol as the user entry point; `_start` remains the default. `-u <symbol>`, `-u<symbol>`, and `--undefined <symbol>` seed checked unresolved-symbol roots before ordered input processing, allowing otherwise-unreferenced archive members to participate in the existing lazy extraction pipeline. `--image-base <address>` accepts a checked unsigned 64-bit hexadecimal (`0x...`) or decimal base and feeds it through the fixed-address `ET_EXEC` layout/emission pipeline; the default remains `0x400000`. `--pie` instead lays the bounded image out from virtual address zero and emits an `ET_DYN` main executable with mapped `PT_LOAD` / `PT_PHDR` metadata and no `PT_INTERP`; `--pie` and `--image-base` are mutually exclusive before input I/O. Load-bias-invariant PC-relative forms (`PC8`/`PC16`/`PC32`/`PC64`/`PLT32`) plus `SIZE32`/`SIZE64` remain direct link-time relocations. The PIE path now accepts two bounded runtime-relocation surfaces. Writable-target `R_X86_64_64` references to image-backed definitions become symbol-free `R_X86_64_RELATIVE` entries, and PC-relative ordinary GOT references (`GOTPCREL` / `GOTPCREL64` / `GOTPCRELX` / `REX_GOTPCRELX`) reuse the deterministic synthetic GOT while adding one `R_X86_64_RELATIVE` per image-backed GOT slot. Multiple references to the same symbol still share one slot and therefore one runtime relocation. `SHN_ABS` GOT targets keep their fixed slot value and do not create a dynamic plane. When any runtime relocation is required, the image gains a real `PT_DYNAMIC` table with `DT_RELA` / `DT_RELASZ` / `DT_RELAENT` / `DT_RELACOUNT`, and a synthetic x86-64 entry trampoline derives the kernel load bias, applies every relative relocation, then transfers control to the selected user entry. PIEs without eligible runtime relocations keep the no-`PT_DYNAMIC` path. Runtime-relative conversion remains restricted to file-backed writable targets and image-backed normal definitions; unresolved weak zero semantics, text relocations, 32-bit absolute forms, GOT32/GOT64/GOT-base/GOTOFF PIE semantics, dynamic TLS relocation, PLT construction, and external dynamic symbol binding remain fail-closed or out of scope. The PIE path now also composes with the existing static TLS model: `R_X86_64_TPOFF32` and `R_X86_64_GOTTPOFF` stay load-bias invariant, TLS-specific GOT slots retain signed thread-pointer offsets rather than becoming runtime-relative GOT entries, and the ET_DYN image carries checked `PT_TLS` metadata. The linker still does not allocate per-thread TLS storage or install a thread pointer; executable fixtures perform explicit single-thread FS-base setup before exercising local-/initial-exec TLS. GNU `readelf` dynamic-relocation differentials verify the emitted metadata, GNU `ld -pie --no-dynamic-linker` supplies the relocation-family reference, and Linux execution dereferences a relocated absolute pointer to prove the self-relocator actually runs. Page alignment remains fixed at `0x1000`. A separate bounded `--shared` producer now emits loader-consumable `ET_DYN` DSOs with a mapped `PT_DYNAMIC`, SysV `DT_HASH`, `DT_STRTAB`, `DT_SYMTAB`, `DT_STRSZ`, and `DT_SYMENT`; exported default-visible global/weak function and data symbols are verified through GNU dynamic inspection plus a real glibc `dlopen`/`dlsym` consumer. The shared-object path accepts three loader-applied relocation slices. Writable-target `R_X86_64_64` references to local/non-preemptible definitions become symbol-free `R_X86_64_RELATIVE` entries. Undefined default-visible strong `STT_OBJECT` references through writable-target `R_X86_64_64` remain symbol-based dynamic relocations backed by matching undefined `.dynsym` entries. Canonical external-data `GOTPCREL` references now reuse the deterministic synthetic GOT: the instruction is resolved at link time to a zero-initialized writable GOT slot, while the loader fills that slot through `R_X86_64_GLOB_DAT`. GNU's synthetic undefined `_GLOBAL_OFFSET_TABLE_` input symbol is recognized as linker-owned only when such a GOT is actually present and is never emitted as a loader import. glibc `dlopen(RTLD_NOW)` fixtures bind both direct and GOT-based imports to data exported by a `-rdynamic` main executable, and the GOT fixture proves an exported DSO function observes subsequent host-side value changes through the patched slot. Internal RELATIVE entries remain first in the combined RELA table so `DT_RELACOUNT` continues to describe exactly the relative prefix. Shared-object alloc layout reserves a nonzero first page so loader-visible defined symbols do not accidentally use `st_value == 0`. Weak-import zero semantics, PLT0/lazy resolver machinery, producer-side RUNPATH/RPATH, system/default loader-path emulation at link time, version-aware provider matching, general interposition, shared-object TLS, general linker scripts, arbitrary section placement, dynamic TLS, and alternate architectures remain outside the current scope. Producer-side SONAME is supported through checked `--soname <name>` / `--soname=<name>`; the emitted `DT_SONAME` shares the loader-visible dynamic string table and is validated by GNU `readelf`. A self-hosting fixture feeds a mini-produced SONAME provider back through the checked `--needed-from` inspector, proves the consumer records that SONAME as `DT_NEEDED`, and then uses glibc `dlopen` with `LD_LIBRARY_PATH` to execute the provider's function/data bindings. The shared CLI can record ordered, deduplicated `DT_NEEDED` dependencies either explicitly with `--needed`, from a checked provider path with `--needed-from`, or through bounded shared-mode `-L/-l` search. Provider-backed dependency paths reuse one checked ELF64 `ET_DYN` inspector: it requires loader-facing `PT_DYNAMIC`, checked SysV `DT_HASH`, GNU `DT_GNU_HASH`, or both, dynsym/strtab metadata, and a non-empty `DT_SONAME`. A root provider that directly matches at least one canonical bounded consumer import preserves the existing direct-provider path. When the root itself matches none, bounded build-time closure inspection follows its checked `DT_NEEDED` graph breadth-first, resolving each dependency only from the current provider directory plus the original shared `-L` search scope, validating every traversed DSO with the same inspector, and deduplicating canonical paths so cycles terminate. A transitive match validates the provider choice without flattening dependency metadata: the consumer still records only the selected root provider SONAME as `DT_NEEDED`, leaving the loader to follow that provider's own dependencies. Shared-mode search prefers `lib<name>.so` over `lib<name>.a` within each search directory; absent `.so` candidates preserve the existing static-archive fallback, while selected DSOs stay out of the ET_REL/archive input stream. A two-provider fixture also proves first-declared `DT_NEEDED` order controls the consumer dependency symbol scope. Strong external `STT_FUNC` symbols are supported through direct writable `R_X86_64_64` function pointers, GOTPCREL/GLOB_DAT slots, and direct `R_X86_64_PLT32` calls. The PLT32 path allocates deterministic RX stubs plus separate writable PLT-GOT slots, publishes symbol-based `R_X86_64_JUMP_SLOT` entries through `DT_JMPREL` / `DT_PLTRELSZ` / `DT_PLTREL`, and sets `DT_BIND_NOW`; a glibc fixture deliberately uses `dlopen(RTLD_LAZY)` to prove the bounded first PLT slice remains eager and does not depend on an unimplemented PLT0 resolver.

Archive support includes a checked System V/GNU/BSD `ar` parser, validated `/` and `/SYM64/` symbol-index parsing, unresolved-symbol-driven lazy member extraction, ordered orchestration for regular `ET_REL` objects plus archives, bounded GNU-style `--start-group ... --end-group` rescanning for circular dependencies across archives, stateful `--whole-archive` / `--no-whole-archive` force inclusion, bounded static `-L` / `-l` library search, GNU-style exact-name `-l:filename` lookup, and GNU-style forced undefined roots. BSD `#1/<len>` extended names are decoded from the inline filename prefix while preserving the raw member header offset and exposing only the remaining bytes as the object payload; malformed lengths and filename ranges are checked before slicing. `-L <dir>`, `-L<dir>`, `--library-path <dir>`, and `--library-path=<dir>` add checked search directories in order; `-l <name>`, `-l<name>`, `--library <name>`, and `--library=<name>` resolve deterministically to the first existing `lib<name>.a` in those directories, while exact-name `:filename` works with the short and long library forms without adding a `lib` prefix or `.a` suffix. The resulting archive remains at the original command-line position. Empty or missing split/equals values are rejected before link input I/O, and a missing exact library reports the requested filename and searched directories. Static/fixed/PIE and partial-link modes keep this bounded archive-only resolver. Shared mode layers checked provider lookup onto the same ordered search directories: each directory prefers `.so` before `.a`, exact `-l:*.so*` names are treated as provider DSOs, and selected providers are validated through the same SONAME/export contract as `--needed-from`. The public `link` CLI preserves left-to-right input order, performs ordinary archive extraction only when an archive is encountered, does not implicitly rescan earlier archives outside an explicit group, and feeds selected archive members through the same validated `LinkerInputObject` and static-link pipeline as regular objects. Forced undefined roots are deduplicated through the resolver's ordered symbol state and are satisfied by earlier regular definitions or by subsequent archive extraction. Whole-archive mode validates and includes every ordinary member in archive order and intentionally does not require a System V/GNU symbol index; special archive members such as `/`, `/SYM64/`, and `//` are not treated as linkable objects. Within a group, the first pass preserves all input order and subsequent passes rescan only ordinary lazy archives; whole-archive inputs are force-included once and are not duplicated by group rescans. The number of lazy group passes is bounded by the checked total number of ordinary members in lazy archives, which is sufficient because every productive rescan must extract at least one previously unselected member. Nested groups are intentionally rejected in this bounded first slice. Extraction validates each selected member as ELF64 x86-64 `ET_REL`, propagates strong undefined references introduced by extracted members, does not let weak undefined references pull additional members, and leaves unreferenced members unparsed outside whole-archive mode. Member headers, sizes, payload bounds, padding, GNU short/long names, BSD extended names, symbol counts, big-endian member offsets, symbol strings, and index-to-member references are validated with checked arithmetic and GNU/LLVM differential coverage. BSD ranlib symbol-table parsing and thin archives remain intentionally unsupported. The companion `mini-elf-ar` CLI provides checked ordinary-member listing (`t`), bounded safe extraction (`x`) with exact-name member selection, and deterministic creation-only indexed archives through `rcs` / `crs`. Creation validates every ELF64 x86-64 `ET_REL` member before filesystem mutation, emits a checked SysV32 symbol index plus GNU long-name table when needed, and refuses to overwrite an existing archive. Extraction validates the complete archive and output plan before creating files, rejects path-traversal-style or duplicate output names, and uses no-clobber creation so existing files and symlinks are never overwritten. Replacement/deletion/reordering, metadata restoration, thin archives, BSD ranlib emission, overwrite mode, and directory-preserving extraction remain outside this bounded slice.

Bounded partial linking emits conventional `ET_REL` output with deterministic `.symtab`, `.strtab`, and `.shstrtab` tables, remapped symbol section indices, and retargeted RELA symbol/target references. Compatible canonical `.text`, `.rodata`, `.data`, and `.bss` contributions are coalesced in input order: each contribution keeps its required alignment, defined symbol `st_value` fields are rebased by the contribution offset, RELA `r_offset` fields are rebased to the merged output section, same-name RELA tables targeting the same canonical output section are combined, and merged `.bss` remains `SHT_NOBITS`. Other allocatable section names remain independent so semantic sections such as `.eh_frame`, TLS sections, and custom alloc sections are not merged accidentally. Cross-object global/weak symbols are canonicalized by name so all original relocation symbol indices retarget one output symbol; undefined references resolve to available definitions, strong definitions supersede weak definitions, multiple real strong definitions fail before output, and `SHN_COMMON` candidates merge by maximum size/alignment while remaining common in the emitted ET_REL. The partial CLI also accepts ordinary indexed archives in the same left-to-right input stream: strong unresolved symbols drive the existing checked lazy-extraction pipeline to a fixed point within each archive, selected members feed the same ET_REL canonicalizer, unreferenced members remain excluded, and later unresolved symbols do not retroactively rescan an earlier archive. Explicit `--start-group ... --end-group` regions reuse the bounded final-link group engine: the first pass preserves input order and later passes rescan only lazy archives, with the number of passes bounded by the checked total ordinary-member count. This resolves circular archive dependencies without changing ordinary non-group ordering. `--whole-archive` / `--no-whole-archive` state is also shared with final linking: every ordinary member is validated and included in archive order, no symbol index is required, and special archive members remain non-linkable metadata. The partial CLI shares the final linker's bounded static-library resolver and forced-undefined argument parser: `-L` / `--library-path`, `-l` / `--library`, exact-name `-l:filename`, and `-u` / `--undefined` roots compose with the same ordered archive pipeline. Forced roots can select otherwise-unreferenced archive members and their transitive dependencies; unmatched roots remain global undefined symbols in the emitted ET_REL, while an existing same-name real global/weak symbol keeps its binding/metadata. Nested partial groups remain fail-closed even though the reusable library resolver can canonicalize balanced nested markers for the final-link CLI. Serializer failures for selected members retain archive/member provenance. GNU `ld -r` differential coverage checks canonical alloc-section counts, contribution alignment, merged relocation offsets/tables, canonical symbol/common records, forced-root behavior, duplicate-definition behavior, transitive archive extraction, and archive ordering; the emitted object is then consumed by both this project's final static linker and GNU `ld -static`, with both executables run on Linux. Identical input order produces byte-identical output, and malformed later inputs fail before the output file is written. Bounded COMDAT handling accepts validated `SHT_GROUP` / `GRP_COMDAT` groups containing preserved allocatable members and their grouped `SHT_RELA` metadata, and now performs deterministic duplicate-signature selection. Grouped alloc sections remain independent from canonical section coalescing; grouped RELA sections keep their flags/alignment/entry-size metadata, are retargeted to the rebuilt static symbol table and remapped group member target, and are emitted before the group so the final `SHT_GROUP` member list can reference their new output section indices. For duplicate `GRP_COMDAT` signatures, the first group in input order wins, matching GNU `ld -r`; loser alloc/RELA members and unreferenced loser globals are discarded before ET_REL emission, while a loser global/weak definition still referenced by surviving relocation metadata is retained as undefined so the relocation remains representable and can resolve against a selected same-name definition. Discarded local definitions remain unmapped so illegal surviving local references fail closed. GNU `readelf --section-groups`, GNU `ld -r`, the project validator, reverse-order selection fixtures, and both mini/GNU final-link execution verify the resulting ET_REL behavior. Grouped RELA must use the group's static symbol table and target another member of the same group; any non-alloc section that retains `SHF_GROUP` without actual membership in a supported `SHT_GROUP` fails closed rather than producing orphan group metadata. The bounded slice also remains fail-closed on `SHN_XINDEX` symbols and non-default nonlocal `st_other` visibility. Dynamic symbol tables, visibility/interposition semantics, unrelated non-allocatable semantic sections, push/pop state in the partial command, non-COMDAT/associative group semantics, broader GNU section-merging rules, shared-library lookup, and general GNU `ld -r` semantics remain outside this phase.

The bounded relocation set includes absolute and PC-relative 8/16/32/64-bit forms already exercised by the static linker, `R_X86_64_SIZE32` / `R_X86_64_SIZE64`, a real static-GOT slice for `R_X86_64_GOT32`, `R_X86_64_GOT64`, `R_X86_64_GOTPCREL`, `R_X86_64_GOTPCRELX`, and `R_X86_64_REX_GOTPCRELX`, plus bounded static TLS support for local-exec `R_X86_64_TPOFF32` and initial-exec `R_X86_64_GOTTPOFF`. SIZE relocations use the resolved definition's ELF `st_size` (`Z`) and apply the ABI `Z + A` formula with checked unsigned-width conversion, so cross-object references do not incorrectly rely on the undefined reference-side symbol metadata. Ordinary GOT-family references collect unique global/weak symbols deterministically, allocate 8-byte entries in a synthetic writable `SHT_PROGBITS` region, and initialize those entries with final resolved symbol addresses. `R_X86_64_GOT32` and `R_X86_64_GOT64` write checked unsigned `G + A` values at 32-bit and 64-bit widths respectively, where `G` is the selected entry's offset from the synthetic GOT base; GOTPCREL-family relocations apply the signed `GOT-entry + A - P` displacement. Initial-exec TLS uses a separate deterministic namespace of GOT slots in that same synthetic region: `GOTTPOFF` relocations address the TLS-specific slot, while the slot itself is materialized after final TLS layout with the signed thread-pointer offset `S - TLS_base - TLS_block_size`. This separation lets ordinary address GOT entries and TLS-offset GOT entries coexist without conflating their value semantics. Static TLS layout emits a checked `PT_TLS` program header spanning initialized `.tdata` and memory-only `.tbss` for both fixed ET_EXEC and bounded ET_DYN PIE output. GNU differential fixtures exercise local-exec and initial-exec behavior; the PIE fixture additionally composes TLS with the self-relocation trampoline and an ordinary runtime-relocated GOT slot, while explicit single-thread FS-base setup keeps process-level TLS allocation outside the linker. The relaxable GOTPCRELX relocation kinds remain accepted as non-relaxed GOT references. The shared-object producer deliberately keeps a narrow runtime-relocation surface: writable-target `R_X86_64_64` references to local/non-preemptible definitions become symbol-free `R_X86_64_RELATIVE`; undefined default-visible strong `STT_OBJECT` references through writable-target `R_X86_64_64` remain symbol-based for loader resolution; and canonical external-data `GOTPCREL` references allocate a synthetic writable GOT slot that is resolved by the loader through `R_X86_64_GLOB_DAT`. Unresolved GOT handling is explicitly scoped to the shared path so ordinary static linking remains fail-closed. Defined default-visible global/weak relocation targets still fail closed because general interposition is not implemented, and undefined weak imports remain outside this bounded slice. Instruction rewriting/relaxation beyond the bounded PLT stub, PLT0/lazy resolver semantics, producer-side RUNPATH/RPATH, system/default loader-path resolution, shared-object TLS, TLSGD/TLSLD and DTPMOD/DTPOFF runtime models, version-aware provider matching, and general symbol interposition remain outside the current bounded linker scope. Producer-side `DT_SONAME` emission is now part of the bounded shared path and composes with checked provider inspection / `DT_NEEDED` inference. Ordered `DT_NEEDED` recording supports explicit names, checked `--needed-from` providers, and one-level shared-mode `-L/-l` provider search; provider-backed paths accept checked SysV `DT_HASH`, GNU `DT_GNU_HASH`, or both, require a non-empty SONAME, and require at least one symbol-type-compatible consumer import. GNU-hash-only providers are validated with checked header/bloom/bucket/chain bounds and derive a bounded dynamic-symbol count from the hash topology when no SysV `nchain` is available. Strong external function symbols can bind through direct writable `R_X86_64_64` slots, GOTPCREL/GLOB_DAT, or eager PLT32 → synthetic PLT → JUMP_SLOT.

Global `SHN_COMMON` tentative symbols are merged by maximum size and alignment, with a real strong definition taking precedence. Surviving commons are placed deterministically by symbol name into one synthetic writable `SHT_NOBITS` region, so existing relocation, symbol-address, load-segment, and link-map paths all observe the same final allocation. Common alignment must be a non-zero power of two, and alignment/size arithmetic is checked for overflow.

## Core roadmap

1. ELF64 header and table-bound validation — complete
2. Validated section and symbol object model — complete
3. RELA parsing and x86-64 relocation validation — complete for the bounded relocation set, including `SIZE32`/`SIZE64`, bounded static GOT families, local-exec `TPOFF32`, and initial-exec `GOTTPOFF`
4. Symbol resolution — complete for the current static-link scope, including bounded `SHN_COMMON` allocation
5. Section layout — complete for the current permission-aware layout model, including synthetic common/GOT regions and bounded static TLS layout
6. ELF executable emission — complete for the current fixed-address static scope plus bounded self-relocating static PIE `ET_DYN` emission; both output modes include checked `PT_TLS` for the static local-/initial-exec slice, while PIE additionally emits mapped `PT_LOAD` / `PT_PHDR` and, when needed, bounded `PT_DYNAMIC` / RELA runtime metadata
7. CLI, selectable entry symbol, deterministic link map, forced undefined roots, and configurable image base — complete
8. System V/GNU/BSD archive parsing, indexed lazy extraction, ordered object/archive orchestration, public CLI integration, bounded archive groups, bounded whole-archive semantics, and bounded static library search — complete for the current archive scope, including exact-name `-l:filename` lookup and split/equals GNU long-option library forms
9. Bounded relocatable partial linking and conventional `ET_REL` emission — complete through canonical `.text` / `.rodata` / `.data` / `.bss` contribution coalescing with canonical RELA aggregation, bounded cross-object global/weak/common symbol canonicalization, validated COMDAT alloc + grouped-RELA metadata preservation with first-wins duplicate-signature selection, ordinary indexed-archive lazy extraction, bounded archive-group rescanning, whole-archive force inclusion, bounded static `-L/-l` library search, and forced undefined roots, including exact-name lookup, checked alignment, symbol-value/RELA-offset rebasing, deterministic metadata, duplicate-strong rejection, left-to-right non-group ordering, and GNU/mini final-link interoperability
10. Bounded static PIE / `ET_DYN` emission — complete through writable-target `R_X86_64_64`, PC-relative ordinary GOT runtime relocation, and static TLS local-/initial-exec integration, including deduplicated ordinary GOT slots, load-bias-invariant TLS offsets, checked `PT_TLS` / `PT_DYNAMIC` metadata, resolution-aware fail-closed boundaries, and GNU/Linux execution evidence
11. Loader-consumable shared-object `ET_DYN` producer — complete through self-contained exports, internal non-preemptible `R_X86_64_RELATIVE`, strong external data/function symbol `R_X86_64_64` binding, PIC external data/function `GOTPCREL` → synthetic GOT → `R_X86_64_GLOB_DAT`, eager direct function `PLT32` → synthetic RX PLT / RW PLT-GOT → `R_X86_64_JUMP_SLOT`, producer-side `DT_SONAME`, explicit/checked-provider `DT_NEEDED`, bounded shared-mode `-L/-l` provider discovery with static-archive fallback, checked SysV/GNU dynamic-hash provider inspection, and bounded transitive provider matching over checked `DT_NEEDED` metadata, including mapped `PT_DYNAMIC`, provider SONAME/export validation, provider-directory / shared-`-L` closure search, canonical-path cycle termination, root-only emitted dependency metadata, undefined import dynsym entries, ordered `DT_RELA` / `DT_RELACOUNT` plus `DT_JMPREL` metadata, `DT_BIND_NOW`, shared-only dependency/import scoping, mini-produced provider self-hosting, fail-closed weak/interposition/TLS boundaries, GNU dynamic inspection, and glibc dependency-loading / `dlopen` / `dlsym` execution evidence
12. Reproducibility and GNU/LLVM semantic differential harness — ongoing hardening work

The current checkpoint is deliberately a bounded ELF toolchain core, not a partial promise of a full system linker. A conventional first-slice `ET_REL` partial-link emitter, a small validated linker-script subset, bounded static TLS local-/initial-exec models, and a self-relocating static `ET_DYN` PIE slice are explicit milestones already in scope. The PIE path now owns a minimal runtime relocation plane for symbol-free `R_X86_64_RELATIVE`, including bounded image-backed ordinary GOT slots reached through PC-relative GOT references, and it can reuse the static TLS local-/initial-exec layout without making TLS GOT slots load-bias relocations. It deliberately stops before a general dynamic linker or TLS runtime. A bounded shared-object producer now owns loader-facing SysV dynamic symbol/hash metadata, an internal symbol-free `R_X86_64_RELATIVE` plane, a direct symbol-based external strong data-import plane through `R_X86_64_64`, and a PIC external-data plane that resolves `GOTPCREL` instructions to synthetic GOT slots patched by loader-applied `R_X86_64_GLOB_DAT`. glibc `dlopen` fixtures prove same-image relocation, direct main-executable symbol binding, mixed RELATIVE/import ordering, and live GOT-based reads of host-exported data. Explicit ordered `DT_NEEDED` dependency recording is now present and glibc fixtures prove DSO-to-DSO provider loading plus first-needed symbol-scope precedence. Provider inference can also validate a root provider through a bounded checked transitive `DT_NEEDED` closure when the root itself exports none of the consumer imports; GNU fixtures prove function/data binding through a middle→deep dependency, shared `-L` closure lookup, missing-dependency fail-closed behavior, and canonical-path cycle termination while the consumer retains only the direct root `DT_NEEDED`. Version-aware provider matching, producer-side RUNPATH/RPATH, system/default loader-path resolution, weak-import semantics, PLT0/lazy-binding resolver semantics, general interposition/versioning, broader GOT32/GOT64/GOT-base/GOTOFF runtime semantics, shared-object TLS, automatic per-thread TLS allocation, dynamic TLS models, and multithread TLS lifecycle remain future architectural phases. Producer-side SONAME is now closed as a milestone: mini-produced providers can carry a checked `DT_SONAME` and round-trip through the project's own provider inspector / dependency inference path before glibc loads the resulting consumer/provider pair. Strong external functions are now callable through loader-patched ordinary GOT slots, direct writable function-pointer relocations, and eager linker-owned PLT/JUMP_SLOT stubs. Broader dynamic linking, the general GNU linker-script language, dynamic TLS models, LTO, and alternate architectures should only enter through explicit future milestones rather than incidental feature growth.

Each new capability should include focused malformed-input tests. Offsets, sizes, addresses, alignment, and relocation arithmetic must use checked operations where overflow can make an input invalid.
