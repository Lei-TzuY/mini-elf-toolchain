# mini-elf-toolchain

A correctness-focused ELF64 x86-64 toolchain/linker laboratory. The project is intentionally staged so each layer is validated before the next one depends on it.

## Current stage

The repository now has checked ELF64 x86-64 paths for both bounded relocatable partial linking (`ET_REL` → `ET_REL`) and final static linking (`ET_REL` → executable). The final-link path runs validated inputs through section extraction, symbol resolution, RELA application, permission-aware layout, `PT_LOAD` / bounded `PT_TLS` construction, and executable emission. The CLI exposes validation commands, `partial -o <output> <input>...`, and a bounded `link -o <output> <input>...` path using `_start` as the default entry symbol, with focused GNU binutils differential coverage.

```sh
mini-elf-toolchain partial -o combined.o start.o support.o
mini-elf-toolchain partial -o combined.o start.o libsupport.a
mini-elf-toolchain link -o a.out combined.o
mini-elf-toolchain link -o a.out start.o support.o
mini-elf-toolchain link -o a.out start.o libsupport.a
mini-elf-toolchain link -o a.out start.o -L ./lib -lsupport
mini-elf-toolchain link -o a.out start.o --library-path ./lib --library support
mini-elf-toolchain link -o a.out start.o -L ./lib -l:custom-support.a
mini-elf-toolchain link -o a.out -u optional_hook start.o -L ./lib -lhooks
mini-elf-toolchain link -o a.out start.o --start-group -L ./lib -lfoo -lbar --end-group
mini-elf-toolchain link -o a.out start.o --whole-archive libextra.a --no-whole-archive
mini-elf-toolchain link -o a.out --map a.out.map start.o support.o
mini-elf-toolchain link -o a.out --entry custom_entry start.o support.o
mini-elf-toolchain link -o a.out --image-base 0x800000 start.o support.o
mini-elf-ar t libsupport.a
mini-elf-ar x libsupport.a support.o
```

The optional deterministic link map records the final entry address, allocatable section provenance and addresses, resolved global/weak symbol addresses, and emitted `PT_LOAD` ranges and permissions. `--entry <symbol>` selects a resolved global/weak symbol as the executable entry point; `_start` remains the default. `-u <symbol>`, `-u<symbol>`, and `--undefined <symbol>` seed checked unresolved-symbol roots before ordered input processing, allowing otherwise-unreferenced archive members to participate in the existing lazy extraction pipeline. `--image-base <address>` accepts a checked unsigned 64-bit hexadecimal (`0x...`) or decimal base and feeds it through the existing layout/emission pipeline; the default remains `0x400000`. Page alignment remains fixed at `0x1000`; general linker scripts, arbitrary section placement, dynamic linking, and alternate architectures remain outside the current scope.

Archive support includes a checked System V/GNU/BSD `ar` parser, validated `/` and `/SYM64/` symbol-index parsing, unresolved-symbol-driven lazy member extraction, ordered orchestration for regular `ET_REL` objects plus archives, bounded GNU-style `--start-group ... --end-group` rescanning for circular dependencies across archives, stateful `--whole-archive` / `--no-whole-archive` force inclusion, bounded static `-L` / `-l` library search, GNU-style exact-name `-l:filename` lookup, and GNU-style forced undefined roots. BSD `#1/<len>` extended names are decoded from the inline filename prefix while preserving the raw member header offset and exposing only the remaining bytes as the object payload; malformed lengths and filename ranges are checked before slicing. `-L <dir>`, `-L<dir>`, `--library-path <dir>`, and `--library-path=<dir>` add checked search directories in order; `-l <name>`, `-l<name>`, `--library <name>`, and `--library=<name>` resolve deterministically to the first existing `lib<name>.a` in those directories, while exact-name `:filename` works with the short and long library forms without adding a `lib` prefix or `.a` suffix. The resulting archive remains at the original command-line position. Empty or missing split/equals values are rejected before link input I/O, and a missing exact library reports the requested filename and searched directories. Shared-library lookup is intentionally not attempted. The public `link` CLI preserves left-to-right input order, performs ordinary archive extraction only when an archive is encountered, does not implicitly rescan earlier archives outside an explicit group, and feeds selected archive members through the same validated `LinkerInputObject` and static-link pipeline as regular objects. Forced undefined roots are deduplicated through the resolver's ordered symbol state and are satisfied by earlier regular definitions or by subsequent archive extraction. Whole-archive mode validates and includes every ordinary member in archive order and intentionally does not require a System V/GNU symbol index; special archive members such as `/`, `/SYM64/`, and `//` are not treated as linkable objects. Within a group, the first pass preserves all input order and subsequent passes rescan only ordinary lazy archives; whole-archive inputs are force-included once and are not duplicated by group rescans. The number of lazy group passes is bounded by the checked total number of ordinary members in lazy archives, which is sufficient because every productive rescan must extract at least one previously unselected member. Nested groups are intentionally rejected in this bounded first slice. Extraction validates each selected member as ELF64 x86-64 `ET_REL`, propagates strong undefined references introduced by extracted members, does not let weak undefined references pull additional members, and leaves unreferenced members unparsed outside whole-archive mode. Member headers, sizes, payload bounds, padding, GNU short/long names, BSD extended names, symbol counts, big-endian member offsets, symbol strings, and index-to-member references are validated with checked arithmetic and GNU/LLVM differential coverage. BSD ranlib symbol-table parsing and thin archives remain intentionally unsupported. The companion `mini-elf-ar` CLI provides checked ordinary-member listing (`t`), bounded safe extraction (`x`) with exact-name member selection, and deterministic creation-only indexed archives through `rcs` / `crs`. Creation validates every ELF64 x86-64 `ET_REL` member before filesystem mutation, emits a checked SysV32 symbol index plus GNU long-name table when needed, and refuses to overwrite an existing archive. Extraction validates the complete archive and output plan before creating files, rejects path-traversal-style or duplicate output names, and uses no-clobber creation so existing files and symlinks are never overwritten. Replacement/deletion/reordering, metadata restoration, thin archives, BSD ranlib emission, overwrite mode, and directory-preserving extraction remain outside this bounded slice.

Bounded partial linking emits conventional `ET_REL` output with deterministic `.symtab`, `.strtab`, and `.shstrtab` tables, remapped symbol section indices, and retargeted RELA symbol/target references. Compatible canonical `.text` contributions are coalesced in input order: each contribution keeps its required alignment, defined symbol `st_value` fields are rebased by the contribution offset, and RELA `r_offset` fields are rebased to the merged output section. Cross-object global/weak symbols are canonicalized by name so all original relocation symbol indices retarget one output symbol; undefined references resolve to available definitions, strong definitions supersede weak definitions, multiple real strong definitions fail before output, and `SHN_COMMON` candidates merge by maximum size/alignment while remaining common in the emitted ET_REL. The partial CLI also accepts ordinary indexed archives in the same left-to-right input stream: strong unresolved symbols drive the existing checked lazy-extraction pipeline to a fixed point within each archive, selected members feed the same ET_REL canonicalizer, unreferenced members remain excluded, and later unresolved symbols do not retroactively rescan an earlier archive. Serializer failures for selected members retain archive/member provenance. Other allocatable sections remain independent in this bounded slice so semantic sections such as `.eh_frame` are not merged accidentally. GNU `ld -r` differential coverage checks merged `.text` offsets, canonical symbol records, common-symbol records, duplicate-definition behavior, transitive archive extraction, and archive ordering; the emitted object is then consumed by both this project's final static linker and GNU `ld -static`, with both executables run on Linux. Identical input order produces byte-identical output, and malformed later inputs fail before the output file is written. The bounded slice fails closed on `SHF_GROUP` / COMDAT sections, `SHN_XINDEX` symbols, and non-default nonlocal `st_other` visibility because the required companion/visibility merge semantics are not yet preserved. Dynamic symbol tables, visibility/interposition semantics, non-allocatable semantic sections, archive groups/whole-archive/library-search in the partial command, COMDAT/group preservation, broad section merging, and general GNU `ld -r` semantics remain outside this phase.

The bounded relocation set includes absolute and PC-relative 8/16/32/64-bit forms already exercised by the static linker, `R_X86_64_SIZE32` / `R_X86_64_SIZE64`, a real static-GOT slice for `R_X86_64_GOT32`, `R_X86_64_GOT64`, `R_X86_64_GOTPCREL`, `R_X86_64_GOTPCRELX`, and `R_X86_64_REX_GOTPCRELX`, plus bounded static TLS support for local-exec `R_X86_64_TPOFF32` and initial-exec `R_X86_64_GOTTPOFF`. SIZE relocations use the resolved definition's ELF `st_size` (`Z`) and apply the ABI `Z + A` formula with checked unsigned-width conversion, so cross-object references do not incorrectly rely on the undefined reference-side symbol metadata. Ordinary GOT-family references collect unique global/weak symbols deterministically, allocate 8-byte entries in a synthetic writable `SHT_PROGBITS` region, and initialize those entries with final resolved symbol addresses. `R_X86_64_GOT32` and `R_X86_64_GOT64` write checked unsigned `G + A` values at 32-bit and 64-bit widths respectively, where `G` is the selected entry's offset from the synthetic GOT base; GOTPCREL-family relocations apply the signed `GOT-entry + A - P` displacement. Initial-exec TLS uses a separate deterministic namespace of GOT slots in that same synthetic region: `GOTTPOFF` relocations address the TLS-specific slot, while the slot itself is materialized after final TLS layout with the signed thread-pointer offset `S - TLS_base - TLS_block_size`. This separation lets ordinary address GOT entries and TLS-offset GOT entries coexist without conflating their value semantics. Static TLS layout emits a checked `PT_TLS` program header spanning initialized `.tdata` and memory-only `.tbss`; GNU differential fixtures exercise both local-exec and initial-exec behavior and execute the resulting ELF on Linux. The relaxable GOTPCRELX relocation kinds remain accepted as non-relaxed GOT references; instruction rewriting/relaxation, PLT construction, shared-object linking, dynamic loading, TLSGD/TLSLD and DTPMOD/DTPOFF runtime models, and symbol interposition remain outside the current bounded linker scope.

Global `SHN_COMMON` tentative symbols are merged by maximum size and alignment, with a real strong definition taking precedence. Surviving commons are placed deterministically by symbol name into one synthetic writable `SHT_NOBITS` region, so existing relocation, symbol-address, load-segment, and link-map paths all observe the same final allocation. Common alignment must be a non-zero power of two, and alignment/size arithmetic is checked for overflow.

## Core roadmap

1. ELF64 header and table-bound validation — complete
2. Validated section and symbol object model — complete
3. RELA parsing and x86-64 relocation validation — complete for the bounded relocation set, including `SIZE32`/`SIZE64`, bounded static GOT families, local-exec `TPOFF32`, and initial-exec `GOTTPOFF`
4. Symbol resolution — complete for the current static-link scope, including bounded `SHN_COMMON` allocation
5. Section layout — complete for the current permission-aware layout model, including synthetic common/GOT regions and bounded static TLS layout
6. ELF executable emission — complete for the current static scope, including checked `PT_TLS` emission
7. CLI, selectable entry symbol, deterministic link map, forced undefined roots, and configurable image base — complete
8. System V/GNU/BSD archive parsing, indexed lazy extraction, ordered object/archive orchestration, public CLI integration, bounded archive groups, bounded whole-archive semantics, and bounded static library search — complete for the current archive scope, including exact-name `-l:filename` lookup and split/equals GNU long-option library forms
9. Bounded relocatable partial linking and conventional `ET_REL` emission — complete through canonical `.text` contribution coalescing, bounded cross-object global/weak/common symbol canonicalization, and ordinary indexed-archive lazy extraction with left-to-right ordering, including checked alignment, symbol-value/RELA-offset rebasing, deterministic metadata, duplicate-strong rejection, and GNU/mini final-link interoperability
10. Reproducibility and GNU/LLVM semantic differential harness — ongoing hardening work

The current checkpoint is deliberately a bounded ELF toolchain core, not a partial promise of a full system linker. A conventional first-slice `ET_REL` partial-link emitter, a small validated linker-script subset, and bounded static TLS local-/initial-exec models are now explicit milestones already in scope. Shared-object linking/dynamic loading, the general GNU linker-script language, dynamic TLS models, LTO, PLT/interposition semantics, and alternate architectures should only enter through explicit future milestones rather than incidental feature growth.

Each new capability should include focused malformed-input tests. Offsets, sizes, addresses, alignment, and relocation arithmetic must use checked operations where overflow can make an input invalid.
