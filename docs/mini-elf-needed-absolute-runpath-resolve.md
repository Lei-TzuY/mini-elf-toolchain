# `mini-elf-needed-absolute-runpath-resolve`

`mini-elf-needed-absolute-runpath-resolve [--ld-library-path <dir[:dir...]>] <symbol> <root-et-dyn> <fallback-library-dir>` extends the checked RUNPATH/RPATH dependency resolver with bounded loader-compatible support for ordinary absolute directory entries and normalized relative non-token directory entries in `DT_RUNPATH` and `DT_RPATH`.

Absolute entries preserve the existing search semantics. Relative non-token entries are resolved against the process current working directory, matching the loader-visible meaning of an unanchored relative search directory rather than rebasing it beneath the declaring shared object's directory. `DT_RUNPATH` remains local to the image that declares it, while legacy `DT_RPATH` remains inheritable by descendants. Explicit loader-path directories retain their existing precedence, SONAME identity de-duplication and breadth-first dependency scope are unchanged, and the final symbol lookup still uses the existing checked GNU/SysV dynamic-hash resolver.

A `DT_NEEDED` string containing `/` is a direct pathname and therefore bypasses inherited RPATH, the explicit loader path, local RUNPATH, and fallback-directory search. In addition to the existing normalized absolute and `$ORIGIN`-anchored forms, this command accepts normalized non-token relative pathnames such as `deps/libleaf.so` and resolves them against the process current working directory. Relative direct pathnames must contain only normal components: empty components, `.`, `..`, and dynamic-token text are rejected before filesystem lookup. The resolved target must be a regular file.

The slice deliberately remains narrower than a host dynamic loader. Absolute search entries must be normalized paths containing only the root plus normal components. Relative non-token search entries must contain one or more normal components and may not contain `.` or `..`; empty RUNPATH/RPATH components map to process cwd. Dynamic tokens embedded in absolute or ordinary relative entries are rejected; the previously supported `$ORIGIN`, `$LIB`, and `$PLATFORM` anchored forms remain available through the checked token-expansion path. Ambient `LD_LIBRARY_PATH`, loader cache/sysroot semantics, secure-execution rules, arbitrary dynamic-string substitution, and general dynamic-loader emulation remain outside this bounded capability.

Focused integration uses GNU `as` / `ld` to construct real ELF64 shared objects and GNU `readelf -dW` to confirm emitted dynamic metadata. Coverage proves direct absolute RUNPATH lookup, inherited absolute RPATH lookup, relative RUNPATH lookup against an explicitly selected process cwd, inherited relative RPATH lookup across a transitive dependency, empty search-path component cwd semantics, normalized cwd-relative direct `DT_NEEDED` lookup, and fail-closed rejection of non-normalized search entries and parent-traversing relative direct dependencies with atomic stdout.
