# `mini-elf-lsda-header`

`mini-elf-lsda-header` adds a bounded LSDA-structure slice on top of the repository's checked GNU `.eh_frame` exception-metadata work. It locates one allocatable `.gcc_except_table` section in an ELF64 x86-64 image, validates the first Itanium-style LSDA header envelope, decodes the declared call-site table as bounded ULEB128 entries, and structurally follows each nonzero action value through the GNU/Itanium action-record chain without interpreting type tables or language-level handler semantics.

```sh
mini-elf-lsda-header ./app
mini-elf-lsda-header ./app ./libexample.so
```

This slice accepts the compact GNU-compatible header tuple used by its focused fixture: omitted LPStart (`DW_EH_PE_omit` / `0xff`), omitted type table (`0xff`), and ULEB128 call-site encoding (`0x01`). The ULEB128 call-site table length is decoded with checked arithmetic and the declared table must remain fully within the file-backed `.gcc_except_table` section.

Each declared call-site entry is decoded strictly inside that table envelope as four ULEB128 fields: start offset, code length, landing-pad offset, and action value. Every field must terminate before the declared table end, `start + length` is checked for `u64` overflow, and the parser must consume the table exactly. Output includes a deterministic entry count plus each entry's bounded interval and raw landing-pad value. These offsets are intentionally not promoted to absolute code or landing-pad addresses because doing so requires the surrounding FDE/LPStart context.

A zero action value remains the Itanium cleanup-only/no-action-record case. A nonzero action value is treated as the ABI's 1-based byte offset from the action table immediately following the call-site table. The referenced action record is decoded as two bounded SLEB128 values: the type filter and the signed displacement to the next action record. As in GCC's personality implementation, a nonzero displacement is applied relative to the cursor immediately after decoding the current type filter. Traversal rejects action offsets outside the section, checked offset arithmetic overflow, truncated/overflowing SLEB128 values, next displacements that leave the action table, and cycles. Output reports each structurally validated record's 1-based action-table offset, raw type filter, and raw next displacement.

The type-filter value is deliberately left uninterpreted in this slice. Positive handler filters, negative exception-specification filters, type-table indexing/matching, landing-pad execution, LPStart-relative address semantics, and language-specific exception behavior remain outside scope. Because the accepted header requires the type table to be omitted, this tool validates action-chain structure rather than claiming C++ catch-type semantics.

ELF section-header table bounds, the section-name string table, section-name offsets/termination, `.gcc_except_table` file ranges, section allocation flags, ULEB128/SLEB128 width, table-length arithmetic, per-entry envelopes, call-site interval arithmetic, action-table offsets, signed next-record arithmetic, and action-chain acyclicity are validated before output. Extended ELF section numbering, multiple exception-table sections, non-omitted LPStart/type tables, other call-site encodings, type tables, landing-pad semantics, and language-specific exception behavior remain outside this bounded slice.

Focused regressions build a real GNU `as` / `ld -shared --eh-frame-hdr` image containing `.cfi_lsda` plus an allocatable `.gcc_except_table`. GNU `readelf -SW` supplies differential evidence for the section virtual address and `readelf -x .gcc_except_table` confirms the exact header/call-site/action bytes consumed by the decoder. Malformed coverage changes the LPStart/type-table/call-site encodings, makes the call-site table length escape the section, truncates a call-site entry, overflows `start + length`, drives an action offset outside the action table or through checked `usize` arithmetic overflow, truncates an action SLEB128, makes a next displacement escape the table, introduces an action-chain cycle, and verifies that a malformed later input leaves stdout empty.
