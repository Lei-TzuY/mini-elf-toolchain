# mini-elf-needed-runpath-resolve

`mini-elf-needed-runpath-resolve [--ld-library-path <dir[:dir...]>] <symbol> <root-et-dyn> <fallback-library-dir>` builds a deterministic breadth-first `DT_NEEDED` closure and resolves the requested external definition through the existing mixed GNU/SysV dynamic-hash resolver. The optional `--ld-library-path` input is explicit rather than read from the ambient process environment so the same command line has reproducible search inputs.

For each image, checked legacy `DT_RPATH` entries participate in dependency search and are inherited by descendants, matching the important loader distinction that legacy RPATH can affect indirect dependencies. A descendant's own `DT_RPATH` entries are searched before inherited ancestor entries and then carried forward. Checked `DT_RUNPATH` remains local to the image that declares it: inherited ancestor RPATH entries are consulted before the explicit loader path, the explicit loader path is consulted before that image's RUNPATH, and the RUNPATH entries themselves are not propagated to grandchildren. If an image contains both tags, `DT_RUNPATH` takes precedence over that image's own `DT_RPATH`. For an image using legacy RPATH without RUNPATH, its effective local/inherited RPATH search remains ahead of the explicit loader path. The fallback directory is always last for basename dependencies.

`--ld-library-path` models the non-secure `LD_LIBRARY_PATH` search layer without importing ambient state. Its value is a colon-separated ordered list of existing directories. Duplicate directories collapse while preserving first occurrence. Empty entries are rejected instead of implying the current working directory, non-directory or unreadable entries fail closed, and dynamic tokens in this explicit input are deliberately unsupported in this slice. This keeps the new search layer deterministic while preserving the loader precedence distinction between legacy RPATH and RUNPATH.

Both ELF path tags use the same bounded expansion rules. `$ORIGIN` / `${ORIGIN}` and `$ORIGIN/<safe-relative-path>` / `${ORIGIN}/<safe-relative-path>` are accepted, entries preserve colon-separated order, and lookup remains confined beneath the declaring image's containing directory. Within an ORIGIN-anchored safe relative path, the x86-64 ELF64 loader tokens `$LIB` / `${LIB}` and `$PLATFORM` / `${PLATFORM}` are accepted only as complete path components. `$LIB` expands deterministically to `lib64`, while `$PLATFORM` expands deterministically to `x86_64`, so forms such as `$ORIGIN/$LIB` and `${ORIGIN}/${PLATFORM}/plugins` are supported without opening unanchored search paths. Empty entries, absolute/unanchored entries, parent traversal, embedded or otherwise unsupported dynamic-token placements, duplicate `DT_RUNPATH` or `DT_RPATH`, malformed dynamic strings, missing dependencies, and non-file candidates fail closed before stdout is emitted. Duplicate effective search directories are collapsed while preserving first occurrence.

A `DT_NEEDED` name that contains `/` is treated as a bounded direct dependency pathname instead of a search name. This slice accepts only `$ORIGIN` / `${ORIGIN}`-anchored direct paths, reusing the same safe-relative-component validation and x86-64 `$LIB` / `$PLATFORM` expansion as RUNPATH/RPATH. Direct dependencies bypass inherited RPATH, the explicit loader path, local RUNPATH, and the fallback directory; the expanded pathname itself must name a regular file. Unanchored, absolute, parent-traversing, or unsupported-token direct names fail closed before any resolver output is emitted.

The dependency scope remains breadth-first: the root is searched first, then direct dependencies in `DT_NEEDED` order, followed by newly discovered transitive dependencies. In addition to collapsing repeated raw `DT_NEEDED` names, each accepted image's checked `DT_SONAME` is registered as a loaded-object identity. A later dependency whose requested basename already matches a loaded SONAME is skipped without another filesystem lookup; if a differently named candidate resolves to an image whose checked SONAME is already loaded, that alias is also suppressed. This preserves first-loaded scope order while avoiding duplicate images under alternate filenames. Malformed, duplicate, out-of-range, or unterminated SONAME metadata fails closed before resolver output.

GNU binutils-backed regression coverage emits legacy RPATH with `ld --disable-new-dtags --rpath=...` and RUNPATH with `ld --enable-new-dtags --rpath=...`, then confirms the tags with `readelf -dW`. The focused inheritance fixture proves that a root RPATH can resolve a grandchild through an intermediate image with no path tag, while the otherwise-equivalent root RUNPATH fixture fails closed because RUNPATH is intentionally not inherited. Explicit-loader-path coverage builds competing libraries with the same SONAME and proves both precedence boundaries: the explicit loader path wins over RUNPATH, while legacy RPATH wins over the explicit loader path. Empty components and non-directory entries fail before any resolver stdout. Additional coverage preserves `${ORIGIN}/${LIB}/...` and `${ORIGIN}/${PLATFORM}/...` literally in emitted dynamic strings and verifies that the resolver reaches the corresponding `lib64` and `x86_64` directories, while embedded token text such as `pre$LIB` or `pre$PLATFORM` is rejected atomically. Direct-path coverage uses GNU `ld -soname` to emit `$ORIGIN/$LIB/$PLATFORM/libleaf.so` as a literal `DT_NEEDED` name, verifies it with `readelf -dW`, and proves that resolution succeeds without consulting RUNPATH/RPATH, explicit loader path, or fallback search; escape and unsupported-token variants remain atomic failures. SONAME-identity coverage uses GNU `ld` and `readelf` to prove that an earlier differently named image advertising a later transitive dependency's SONAME suppresses reopening that name; the fallback canonical file is deliberately malformed so success demonstrates that the alias lookup was skipped. A malformed discovered SONAME offset is rejected atomically.

This slice intentionally does not read ambient `LD_LIBRARY_PATH`, model secure-execution suppression, expand dynamic tokens inside the explicit loader-path input, implement absolute or cwd-relative direct `DT_NEEDED` paths, accept unanchored relative RUNPATH/RPATH entries, search the ld.so cache/default system directories, perform arbitrary dynamic-string substitutions, match symbol versions during scope lookup, execute IFUNC resolvers, model loader namespaces/dlopen identity rules, or apply relocations.
